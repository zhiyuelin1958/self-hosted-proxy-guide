# 07 防直连（可选）

## 1. 问题：客户端一关，流量就漏回本地

分流只在客户端运行时生效。Clash Mi 关闭、崩溃、开机后还没启动，或者你临时换了别的代理时，指定服务就会从本地网络或别的出口出去。这样它会看到同一个账号时而从第二出口、时而从别处访问。

**防直连的目标**：在客户端之外再固定一条路径，指定服务只能走这条路径。路径不通时连接直接失败（fail-closed），不回退。

| 层 | 设备 | 原理 | 难度 |
|---|---|---|---|
| A | Windows 的 Chrome / Edge | 浏览器策略强制这些域名只走本地代理端口 | 低 |
| B | iPhone、iPad | 系统中继描述文件，把这些域名交给服务器上的独立中继；中继只在隧道内可达 | 高 |
| C | WSL / Linux 命令行工具 | 启动前检查出口，不符合就不启动 | 低 |

三层都用同一份指定服务域名清单。

## 2. A 层：Windows Chrome / Edge 浏览器策略

### 原理

Chrome 和 Edge 支持通过注册表下发“企业策略”。脚本 [client/windows/browser-fail-closed.ps1](../client/windows/browser-fail-closed.ps1) 写入两项策略，只对当前 Windows 用户生效：

| 策略 | 值 | 作用 |
|---|---|---|
| `ProxySettings` | 内嵌 PAC 脚本，`ProxyPacMandatory=true` | 名单内域名只返回 `PROXY 127.0.0.1:3067`，**没有 `DIRECT` 备用**；其他域名返回 `PROXY 127.0.0.1:3067; DIRECT`，代理不在时还能直连 |
| `WebRtcIPHandling` | `disable_non_proxied_udp` | WebRTC 不得绕过代理发 UDP，避免泄露本地 IP |

PAC 以 `data:` URL 的形式内嵌在策略里，不依赖本地文件。`ProxyPacMandatory` 保证 PAC 出错时不会退回直连。

Clash Mi 退出后 `3067` 不再监听，名单内域名在浏览器里报 `ERR_PROXY_CONNECTION_FAILED`，普通网站照常直连。

### 安装

以管理员身份打开 PowerShell，在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\client\windows\browser-fail-closed.ps1 `
  -Action Install -DomainsFile .\templates\protected-domains.example.json -Port 3067
```

脚本首次安装时会把原有策略备份到 `%LOCALAPPDATA%\ProxyFailClosed\`。重启浏览器，或打开 `chrome://policy`、`edge://policy` 点“重新加载策略”。

回退：把 `-Action Install` 改为 `-Action Remove`，恢复安装前的策略。

### 验收

1. Clash Mi 开启：名单内检测站显示第二出口，普通网站正常。
2. 完全退出 Clash Mi，确认 `3067` 不再监听：

   ```powershell
   Get-NetTCPConnection -LocalPort 3067 -State Listen -ErrorAction SilentlyContinue
   ```

3. 浏览器打开名单内网站，应报代理连接错误；打开国内网站，正常。
4. 重新开启 Clash Mi，恢复第二出口。

### 局限

- 只覆盖 Chrome / Edge，不覆盖其他浏览器和桌面程序；
- 每个 Windows 用户需分别安装；
- 名单变化后需重新执行安装；
- 备用客户端占用同一个 `3067` 时，浏览器策略拦不住，要在备用客户端里拒绝名单内域名。

## 3. B 层：iPhone、iPad 独立中继（进阶）

### 原理

iOS 17 起支持“网络中继”（[Apple Relay 描述文件](https://developer.apple.com/documentation/devicemanagement/relay)，类型 `com.apple.relay.managed`）。对 `MatchDomains` 中的域名，系统通过指定的 HTTP/2 中继发起连接。设置 `AllowDNSFailover=false` 后，中继不可用时连接直接失败。

中继描述文件和 Clash Mi 是**叠加**关系：Clash Mi 开着时，名单内域名仍先交给中继，去中继的连接再进 VLESS 隧道。利用这一点，中继只在隧道内开放：

```text
iPhone（MatchDomains 内的域名）
   │ HTTP/2 CONNECT 到 <SERVER_IP>:8443，带 Proxy-Authorization
   ▼
Clash Mi ──VLESS 隧道──► 入口服务器主 Xray
   │ 首条路由规则：目标 <SERVER_IP>:8443 → relay-private 出站
   ▼ （freedom 重定向到 10.231.252.2:18443）
网络命名空间 app-relay 内的 Envoy
   │ 认证 + CONNECT / CONNECT-UDP 动态转发
   ▼ （命名空间内所有出站都被 TPROXY 截走）
中继专用 Xray :18445（只监听回环）── socks 出站 exit2
   ▼
第二出口 ──► 目标服务
```

结果：

| 状态 | 名单内域名 |
|---|---|
| Clash Mi 开启 | 经中继、从第二出口访问 |
| Clash Mi 关闭，或改用其他代理 | 连不上中继，访问失败 |
| 中继或第二出口故障 | 访问失败，不绕行 |

公网上 8443 没有监听。中继如果对公网开放，未认证的访问会拿到 `407` 和认证域名，很容易被扫描识别；它和 443 共用一个 IP，暴露后可能连累入口。

| 设计 | 目的 |
|---|---|
| 主 Xray 的 `relay-private` 出站 | 只有隧道内的连接能到中继 |
| Envoy 放在独立网络命名空间里 | 它没有直接上网的路径，出站只能经 TPROXY 交给 `exit2`，第二出口挂掉时只能失败 |
| 命名空间内拒绝私有网段 | 中继不能被用来访问服务器内网 |
| 独立的 systemd 单元和独立的 Xray 进程 | 和主 Xray 互不影响，可以单独停用 |
| 公网可信的 IP 证书 | iOS 要求中继的 TLS 证书可信；没有域名时用 Let's Encrypt 的 IP 证书（约 6 天有效，自动续期） |
| 每用户一组账号密码 | 写进各自的描述文件，Envoy 校验 `Proxy-Authorization` |
| 下载路径带随机令牌 | 描述文件和手机的 Clash Mi 订阅由 Envoy 直接返回，同样只能经隧道下载 |

### 部署步骤

脚本在 [server/relay/](../server/relay/)，以 root 在服务器上执行：

1. 编辑 `relay_settings.py`，填入 `PUBLIC_HOST`（服务器 IP）和 `EGRESS_TAG`（第二出口的出站 tag，默认 `exit2`）。
2. 把 `server/relay/` 和域名清单（命名为 `protected-domains.json`）复制到服务器，运行 `python3 prepare_relay.py`。它下载并校验 Envoy、生成账号、写配置和 systemd 单元，**不启动服务、不开端口**，最后输出要加进主 Xray 的出站和路由规则。
3. 把输出的 `relay-private` 出站加进主 Xray 的 `outbounds`，路由规则放在 `routing.rules` **第一条**（在 `geoip:private` 阻断规则之前）：

   ```json
   {"tag": "relay-private", "protocol": "freedom", "settings": {
     "redirect": "10.231.252.2:18443",
     "finalRules": [{"action": "allow", "network": "tcp", "ip": ["10.231.252.2/32"], "port": "18443"}]}}
   ```

   ```json
   {"type": "field", "ip": ["<SERVER_IP>/32"], "port": "8443", "network": "tcp", "outboundTag": "relay-private"}
   ```

   Xray 默认不许经 VLESS 入站访问私有地址，`finalRules` 只放行中继这一个地址和端口。改完 `xray run -test` 通过再重启。
4. 申请 IP 证书。需要 Certbot 5.4 以上，装在独立虚拟环境里；申请时临时放行 TCP 80：

   ```bash
   python3 -m venv /opt/app-relay/acme
   /opt/app-relay/acme/bin/pip install 'certbot>=5.4'
   ufw allow 80/tcp
   /opt/app-relay/acme/bin/certbot certonly --standalone \
     --preferred-profile shortlived --ip-address <SERVER_IP> \
     --cert-name app-relay-ip -m <你的邮箱> --agree-tos
   ufw delete allow 80/tcp
   ```

   先加 `--staging` 试一次更稳妥。
5. `python3 enable_renewal.py`：安装续期钩子和定时器，复制证书，启动 `app-relay.target`。续期定时器每天检查两次，续期期间临时放行 TCP 80。
6. 先用测试描述文件（只匹配 `www.cloudflare.com`）在手机上验证，再运行 `python3 publish_profiles.py --publish` 生成正式描述文件，输出里有每位用户的下载地址。

### 在手机上安装与验收

1. 开着 Clash Mi，用 Safari 打开自己的下载地址，到“设置 → 已下载描述文件”安装。连不上时，把描述文件用局域网工具传到手机安装。
2. 用 `ident.me` 作出口探针，把它放进域名清单。它在国内可以直连：如果发生了直连，它会回显国内 IP，一眼就能看出来。不要用指定服务本身作探针，国内直连它多半也是失败，看不出是否直连。
3. 逐项检查：

   | 状态 | 期望 |
   |---|---|
   | Clash Mi 开启 | `ident.me` 回显第二出口 IP；指定服务 App 正常 |
   | 关闭 Clash Mi | `ident.me` 和指定服务都失败 |
   | 改用其他代理 App | 同上 |
   | 切换 Wi-Fi / 蜂窝网络 | 同上，没有短暂直连 |
   | 服务器上 `systemctl stop app-relay-egress` | 名单内域名失败，普通网站正常；之后 `systemctl start app-relay.target` 恢复 |

4. 切换状态后 App 卡住时，从后台完全划掉 App 再打开，已建立的连接不会自动迁移。
5. 升级 iOS（包括小版本）后，重测第 3 步。

### 局限

- 按域名生效，清单变化后要重新发布描述文件，并在手机上重新安装；
- 移除描述文件即解除保护；
- IP 证书会进入证书透明度日志，续期时 TCP 80 短暂开放，这是剩下的暴露面。

## 4. C 层：命令行工具的启动前检查（WSL / Linux）

### WSL 网络准备

Windows 11 22H2 及以上，在 `%USERPROFILE%\.wslconfig` 中加入下面几行（已有 `[wsl2]` 节就合并），也可参考 [client/wsl/wslconfig.example](../client/wsl/wslconfig.example)：

```ini
[wsl2]
networkingMode=mirrored
autoProxy=true
dnsTunneling=true
```

PowerShell 执行 `wsl --shutdown` 后重新进入。效果：

| 选项 | 作用 |
|---|---|
| `mirrored` | WSL 与 Windows 共享网络，可通过 `127.0.0.1` 访问 Windows 上的 Clash Mi |
| `autoProxy` | WSL 自动继承 Windows 的系统代理 |
| `dnsTunneling` | DNS 交给 Windows 处理，受 Clash Mi 的 DNS 规则控制 |

没有代理环境变量的程序由 Clash Mi 的 TUN 接管。参考 [Microsoft WSL 网络说明](https://learn.microsoft.com/windows/wsl/networking)。

### 启动前检查脚本

[client/wsl/egress-guard.sh](../client/wsl/egress-guard.sh) 在启动某个命令前，请求一个检测地址；只有返回的 `ip` 和 `loc` 都符合预期才执行命令，否则退出：

```bash
install -m 755 client/wsl/egress-guard.sh /usr/local/bin/egress-guard
# 用法：egress-guard <检测URL> <期望IP> <期望地区> -- <命令> [参数...]
egress-guard https://www.cloudflare.com/cdn-cgi/trace 198.51.100.20 SG -- curl -I https://example.com
```

可以为常用工具写一个同名包装脚本，放在 `PATH` 中优先于原程序的位置（如 `/usr/local/bin/<工具名>`），内部调用 `egress-guard ... -- /真实/路径/<工具名> "$@"`。注意：

- 它**只在启动前检查**，运行中仍须保持 Clash Mi 连接，不等于持续断网保护；
- 工具自身的升级程序可能覆盖包装脚本。关闭工具的自动更新，手动升级前把包装脚本复制一份，升级后再放回去。
