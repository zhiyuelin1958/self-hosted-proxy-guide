# 05 客户端与分流（Clash Mi）

Clash Mi 的节点、分流规则、DNS 都写在一个 YAML 文件里。本章从示例配置 [client/clashmi/config.example.yaml](../client/clashmi/config.example.yaml) 改出自己的配置，再导入各台设备。界面路径以 Clash Mi 1.0.32 为准。

## 1. 改出自己的配置

复制示例文件，改名为 `*.local.yaml`（`.gitignore` 会忽略它），然后修改：

| 位置 | 改成 |
|---|---|
| `proxies` 里的 `<...>` | 服务器 IP、UUID、SNI、REALITY 公钥、shortId |
| `secret` | 一串随机字符，保护本机控制接口 |
| `rules` 第 2 段与 `nameserver-policy` 中的 `example-service.com` 等 | 你的指定服务域名清单；不做二级出口就删掉这一段 |
| `your-school.edu.cn` | 你学校或单位的域名，没有就删掉 |
| `example-cn-site.com` | 国内域名库漏掉的常用国内网站，按需增删 |

指定服务的域名要在 `rules` 和 `nameserver-policy` 两处都写：`rules` 决定走代理，`nameserver-policy` 让它们经代理解析。

## 2. 规则顺序

| 顺序 | 规则 | 动作 | 为什么放这里 |
|---|---|---|---|
| 1 | UDP 443 | 拒绝 | 禁用 HTTP/3，浏览器改用 HTTP/2 走隧道 |
| 2 | 指定服务域名和 IP 段 | 代理 | 最先匹配，避免其子域名被国内库误判直连 |
| 3 | UDP 3478、5349、19302～19309 | 代理 | STUN 端口，避免 WebRTC 用本地 IP |
| 4 | 校园域名、私有网段 | 直连 | 校内资源和局域网必须直连 |
| 5 | 个人补充的国内域名 | 直连 | 弥补域名库遗漏 |
| 6 | `cn-domain`、`cn-ip` 规则集 | 直连 | MetaCubeX 的国内域名库与中国 IP 库 |
| 最后 | `MATCH` | 代理 | 其余全部走代理 |

规则集每 24 小时更新一次，经代理下载（直连 GitHub 常常失败）。首次启用时保持节点可用，等规则下载完；之后即使代理不可用，客户端也会用缓存的规则启动。

## 3. DNS

| 流量 | DNS |
|---|---|
| 校园域名 | `system`（系统 DNS），校内域名常只在校内 DNS 可解析 |
| 国内域名、个人补充 | 直连的阿里 DoH `https://223.5.5.5/dns-query` |
| 指定服务与其余流量 | 经代理的 `https://1.1.1.1/dns-query`、`https://8.8.8.8/dns-query` |

`respect-rules: true` 让 DNS 查询本身也按规则走代理或直连。示例配置关闭了 IPv6 解析；`enhanced-mode` 用 `redir-host`，应用拿到的是真实 IP。

## 4. Windows 端

**导入**：Clash Mi 里添加配置，选“本地文件”，导入自己的 `.local.yaml`，“覆写”选“不覆写”。`PROXY` 组只放自己的节点。

**本机端口**：都只监听 `127.0.0.1`，局域网其他设备访问不到。

| 端口 | 用途 |
|---|---|
| `127.0.0.1:3067` | 规则模式的 HTTP/SOCKS 代理，浏览器策略、编辑器、WSL 都指向这里 |
| `127.0.0.1:3066` | 全部走代理，测试用 |
| `127.0.0.1:3065` | 全部直连，测试用 |
| `127.0.0.1:3057` | 控制接口 |

VS Code 及其插件、其他编辑器：在设置中把 HTTP 代理设为 `http://127.0.0.1:3067`。

**TUN**：开启 TUN 和严格路由，接管不认代理设置的程序和 UDP。Windows 版 Clash Mi 的 TUN 参数以安装目录下 `service_core_setting.json` 的 `tun` 段为准，配置文件里的 `tun` 段不生效。在那里加上：

```json
"route-exclude-address": ["<SERVER_IP>/32"]
```

去往入口服务器的流量于是绕开 TUN，从物理网卡出去，健康检查才能判断入口本身是否被封。在界面上改 TUN 设置可能把这一项丢掉，改完要回去确认。

**开机自启**：在 Clash Mi 设置里打开开机启动和自动连接。TUN 需要管理员权限时，用“任务计划程序”新建一个“登录时、以最高权限运行”的任务来启动 Clash Mi。

## 5. iPhone 与 iPad

手机用同一份配置，去掉 `listeners` 段、`tun` 段里的 `route-exclude-address`，以及 `rule-providers` 里的 `path`。手机上不能排除入口 IP：做 iPhone 中继时，去中继的连接要经过隧道。

把配置文件传到手机：用 LocalSend 等局域网工具发送，不经聊天软件和邮箱。在“文件”App 里分享给 Clash Mi 导入，选自己的节点、规则模式并连接。首次连接需允许添加 VPN 配置。

做了 iPhone 中继后，可以把这份配置也放到中继的下载地址上，作为订阅导入，以后改配置时手机每 24 小时自动更新。

## 6. 初步检查

断开再重新连接，然后打开：

| 页面 | 期望 |
|---|---|
| <https://www.cloudflare.com/cdn-cgi/trace> | `ip=<SERVER_IP>`、`loc=` 服务器所在地 |
| 国内常用网站、学校或单位网站 | 正常，速度和不开代理时一样 |
| 指定服务的检测页（做了二级出口时） | 第二出口的 IP |

Clash Mi 的“连接”页能看到每个连接命中了哪条规则、走了哪个出站，排查分流问题时最直接。
