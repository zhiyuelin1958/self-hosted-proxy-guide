# 05 客户端与分流（Karing）

界面路径以 Karing 1.2.25 为准，其他版本菜单名可能略有不同。若看不到某些选项，先在设置中**关闭“新手模式”**。

## 1. 导入节点

1. 复制第 04 章生成的整行 `vless://...` 链接；
2. Karing 首页 → 添加配置 → 从剪贴板导入；
3. 首页选中该节点。

每位用户只导入自己的链接。两人共用一个 UUID 也能用，但无法分别统计、也无法单独停用某人。

## 2. 电脑端：接管方式

Windows 上建议同时开启：

| 设置 | 作用 |
|---|---|
| 系统代理 | 浏览器等遵守系统代理的程序 |
| TUN | 接管不认系统代理的程序和 UDP |
| 严格路由 | 防止流量绕开 TUN |

Karing 默认在本机开几个端口（以设置页显示为准）：

| 端口（示例） | 用途 |
|---|---|
| `127.0.0.1:3067` | 规则模式的 HTTP/SOCKS 代理，编辑器插件等显式指向这里 |
| `127.0.0.1:3066` | 全局代理 |
| `127.0.0.1:3065` | 强制直连 |
| `127.0.0.1:3057` | 控制接口 |

都只监听 `127.0.0.1`，局域网其他设备访问不到，这是期望的。

VS Code 及其插件、其他编辑器：在设置中把 HTTP 代理设为 `http://127.0.0.1:3067`。

**开机自启**：在 Karing 设置里打开开机启动和自动连接。如果 TUN 需要管理员权限，用“任务计划程序”新建一个“登录时、以最高权限运行”的任务来启动 Karing。

## 3. 导入分流规则

分流规则和节点分开保存。仓库提供示例 [client/karing/routing-groups.example.json](../client/karing/routing-groups.example.json)，先按你的情况修改：

- “指定出口：优先代理”组：把 `example-service.com` 换成你需要固定出口的服务域名（不需要第 06 章就删掉这一组）；
- “校园网络：直连”组：把 `your-school.edu.cn` 换成你学校/单位的域名，没有就删掉该域名、保留私有网段；
- “国内常用域名：直连”组：按自己常用的国内网站增删。

然后打包导入：

1. 把文件重命名为 `karing_routing_group.json`，压缩成 zip（zip 内只有这一个文件）；
2. 在接收设备上，先进入“设置 → 备份和同步 → 局域网同步 → 文件导入/导出”，**导出一份完整备份**；
3. 同一页面导入刚才的 zip。

导入会替换自定义分流组定义，保留已有节点。

> 这个 JSON 格式取自 Karing 1.2.25 的导出文件。如果你的版本不同，先在 Karing 里手动建一个分流组并导出，对照导出文件的结构修改。

## 4. 设置分流组顺序与动作

进入“设置 → 分流 → 分流规则”，按下表顺序启用各组并设置动作：

| 顺序 | 分流组 | 动作 | 为什么放这里 |
|---|---|---|---|
| 1 | 指定出口：优先代理 | 当前选择 | 最先匹配，避免其子域名被国内库误判直连 |
| 2 | STUN：优先代理 | 当前选择 | UDP 3478、5349、19302～19309，避免 WebRTC 用本地 IP |
| 3 | 校园网络：直连 | 直连 | 校内资源和私有网段必须直连 |
| 4 | 国内常用域名：直连 | 直连 | 个人补充，弥补域名库遗漏 |
| 5 | 国内域名库：直连 | 直连 | MetaCubeX `geosite:cn` |
| 6 | 中国IP库：直连 | 直连 | 兜住直接连 IP 的国内应用 |
| 最后 | final | 当前选择 | 其余全部走代理 |

`final` 在“分流规则”页最下方，是内置项，不用新建。首页模式选**规则**，分流才生效（全局模式会忽略这些规则）。

## 5. 设置 DNS

进入“设置 → DNS”：

- **启用 DNS 分流规则**：开启；
- **「直连流量」启用 ECS**：关闭；
- **「代理流量」解析通道**：选择“通过代理连接 DNS”。旧版对应的是“「代理流量/final」通过代理服务器解析 DNS”开关，打开它。

打开各类 DNS 服务器列表，只保留下表地址：

| 类别 | 保留的地址 |
|---|---|
| DNS 服务器（基础解析） | `local`、`https://223.5.5.5/dns-query` |
| 代理服务器（解析节点地址） | `local`、`https://223.5.5.5/dns-query` |
| 直连流量 | `local`、`https://223.5.5.5/dns-query` |
| 代理流量 / final | `https://1.1.1.1/dns-query`、`https://8.8.8.8/dns-query` |

列表里没有就点“添加”，填完整地址。

再回到“设置 → 分流 → 分流规则”，点进下列分流组的“DNS”，每组只选一项：

| 分流组 | DNS |
|---|---|
| 校园网络：直连 | `local` |
| 国内常用域名：直连 | `https://223.5.5.5/dns-query` |
| 国内域名库：直连 | `https://223.5.5.5/dns-query` |

指定出口、STUN、中国 IP 库三组保持默认：前两组走代理，由“代理流量”的 DNS 处理；IP 库按目标 IP 匹配，不需要为它单独指定 DNS。

## 6. 规则自动更新

“设置 → 分流 → RuleSet”：

- 更新间隔设为 **24 小时**（单位为秒时填 `86400`）；
- 在“Rule Set 直连下载”名单中删掉 `raw.githubusercontent.com`，让规则经代理下载（直连 GitHub 常常失败）；
- 首次启用时保持节点可用，等规则下载完。之后即使代理不可用，客户端也会用缓存的规则启动。

## 7. 重连并初步检查

1. 首页选你的节点，模式“规则”；
2. 断开再重新连接；
3. 打开：

| 页面 | 期望 |
|---|---|
| <https://www.cloudflare.com/cdn-cgi/trace> | `ip=<SERVER_IP>`、`loc=` 服务器所在地 |
| 国内常用网站、学校/单位网站 | 正常、速度和不开代理时一样 |

如果做了第 06 章，再加一项：指定服务的 trace 页应显示第二出口。完整测试见[第 08 章](08-测试与验收.md)。

## 8. 同步到其他设备

- 每台设备都要：导入自己的节点 → 导出备份 → 导入分流 zip → 完成第 4～6 节设置 → 第 7 节检查；
- 手机和电脑设置项相同，iOS 版首次连接需允许添加 VPN 配置；
- 出现问题时，导入第 3 节保存的该设备备份即可回到原状态。
