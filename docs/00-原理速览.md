# 00 原理速览

动手前先弄清每个部件解决什么问题。后面章节的每个配置项都能在这里找到“为什么”。

## 1. 代理在做什么

不用代理时，浏览器直接连目标网站：

```text
浏览器 ──TCP/TLS──► 目标网站
```

用代理时，浏览器先连到你的服务器，由服务器替你去连目标网站：

```text
浏览器 ──► 本机客户端 ──加密隧道──► 你的服务器 ──► 目标网站
```

目标网站看到的来源 IP 是**服务器的 IP**，本地网络只看到你在和服务器通信。

## 2. 为什么普通加密还不够

网络审查和干扰常见有几种手段：

| 手段 | 做法 | 对应的对策 |
|---|---|---|
| DNS 污染 | 对特定域名返回错误 IP | 国外域名经代理或加密 DNS（DoH）解析 |
| IP 封锁 | 直接丢弃发往某 IP 的包 | 使用自己的、未被封锁的服务器 IP |
| SNI 检查 | TLS 握手里的 SNI 明文写着要访问的域名 | 让握手看起来是访问一个正常网站 |
| 主动探测 | 怀疑某端口是代理时，主动连上去试探 | 未认证的探测得到的是正常网站的响应 |
| 流量特征 | 识别“TLS 里再套 TLS”等统计特征 | XTLS-Vision 去掉 TLS 嵌套的特征 |

## 3. VLESS、REALITY、XTLS-Vision 各管什么

- **VLESS**：一个很薄的代理协议，只负责“我是谁（UUID）、要连哪里”。它本身不加密，加密交给下层的 TLS / REALITY。
- **REALITY**：替代普通 TLS。客户端握手时的 SNI 写的是一个真实、常见的网站（称为“目标网站”，配置里的 `dest` / `serverNames`）。服务端用 x25519 密钥判断来者是不是自己的客户端：
  - 是自己的客户端 → 进入代理；
  - 不是（例如探测者）→ 把连接原样转发给真实的目标网站，探测者看到的就是那个网站的真证书。

  因此你**不需要自己的域名和证书**，服务器看起来就像在“转发一个大网站”。
- **XTLS-Vision**（`flow: xtls-rprx-vision`）：你访问的网站本身大多也是 HTTPS，于是出现“TLS 里套 TLS”。Vision 会在内层 TLS 握手完成后直接拼接，避免这种可统计的特征，同时减少一次加解密开销。

## 4. 分流：哪些走代理，哪些直连

全部走代理会让国内网站变慢，也浪费服务器流量。国内服务看到海外 IP，还可能触发风控。规则模式按下面的顺序匹配：

```text
1. 指定服务（可选，要求固定出口） → 代理
2. STUN / 实时通信端口           → 代理（避免 WebRTC 泄露本地 IP）
3. 校园网 / 局域网 / 私有地址      → 直连
4. 个人补充的国内域名             → 直连
5. 国内域名库（geosite:cn）       → 直连
6. 中国 IP 库（geoip:cn）         → 直连
7. 其余（final）                 → 代理
```

顺序很重要：**先匹配的规则先生效**。指定服务放最前，是为了防止它的某个子域名恰好落在国内域名库里而被直连。中国 IP 库放在后面，用来兜住“没有域名、直接连 IP”的应用（例如部分即时通讯的文件下载）。

## 5. DNS 为什么也要分流

访问一个网站先要把域名解析成 IP。DNS 处理不当会带来两个问题：

- **被污染**：用国内 DNS 解析国外域名，可能拿到错误 IP。
- **泄露**：网站可以在页面里嵌入随机子域名，看是谁来解析它。如果你走代理访问，却用国内 DNS 解析，网站就会看到“海外 IP + 中国解析器”这种不一致的组合。

本教程的做法：

| 流量 | 用哪个 DNS |
|---|---|
| 校园网域名 | 系统 DNS（`local`），因为校内域名常只在校内 DNS 可解析 |
| 国内域名 | 直连的国内 DoH（如阿里 `https://223.5.5.5/dns-query`） |
| 代理流量 | 经代理连接的国外 DoH（如 `1.1.1.1`、`8.8.8.8`） |

另外，关闭直连流量的 ECS（EDNS Client Subnet）。开启 ECS 时，DNS 查询会附带你所在的网段。

## 6. 系统代理与 TUN

| 方式 | 原理 | 覆盖范围 |
|---|---|---|
| 系统代理 | 设置 Windows 的 HTTP 代理为 `127.0.0.1:端口` | 只有遵守系统代理设置的程序（浏览器等） |
| TUN | 建一块虚拟网卡，把系统路由指向它 | 几乎所有程序，包括不认代理设置的、UDP 流量 |
| 严格路由 | TUN 模式下阻止流量绕开虚拟网卡 | 堵住绕开 TUN 的流量 |

电脑上建议同时开系统代理、TUN 和严格路由，编辑器插件等再显式指向本地 HTTP 端口。

## 7. 二级出口与防直连（进阶）

- **二级出口**：服务器收到流量后，按域名决定自己出去，还是交给另一个代理出去。适合某些服务需要固定地区、固定 IP 出口，而其他流量没必要绕远路的情况。见[第 06 章](06-二级出口.md)。
- **防直连**：客户端一关，所有程序都回到本地网络直连。要求出口一致的服务会看到同一个账号时而在 A 地、时而在 B 地。防直连在客户端之外再加一层限制：只许走指定路径，走不通就失败。见[第 07 章](07-防直连.md)。
