# 10 故障排查

## 定位顺序

从里到外一段一段排除，不要同时改多处：

```text
① 服务器进程 → ② 服务器端口与防火墙 → ③ 客户端节点参数 → ④ 客户端模式与分流 → ⑤ DNS → ⑥ 二级出口 → ⑦ 防直连
```

| 段 | 检查 |
|---|---|
| ① | `systemctl status xray`；`journalctl -u xray -n 100 --no-pager` |
| ② | `sudo ss -tlnp \| grep 443`；`sudo ufw status`；云安全组入站规则 |
| ③ | 链接里的 UUID、`pbk`（公钥）、`sid`、`sni`、端口是否与服务端一致 |
| ④ | 首页是否为“规则”模式；Karing“连接”页看命中的规则和出站 |
| ⑤ | DNS 设置是否按第 05 章；临时换成全局模式对比 |
| ⑥ | 服务器上直接 `curl --socks5-hostname` 测第二出口 |
| ⑦ | 临时移除策略/描述文件，看问题是否消失 |

## 常见问题

### 完全连不上，Karing 显示超时

先在服务器上看 Xray 是否 `active`、是否监听 443；再确认云安全组和 `ufw` 都放行了 443。换个网络（手机热点）试一次，区分是服务器问题还是当前网络问题。

### 日志里出现 `REALITY: processed invalid connection` 或握手失败

客户端参数与服务端不匹配：最常见的是把**私钥**当成 `pbk` 填进链接，或 `sid` 不在 `shortIds` 列表中，或 `sni` 不在 `serverNames` 中。也可能是 `minClientVer` 设得比客户端内核版本高。

### 升级 Xray 后客户端连不上了

用 `xray-restore` 回到升级前的快照，确认恢复正常；再查新版本的发布说明，看是否有默认值变化。替换二进制前，先按第 09 章的升级策略验证。

### 国内网站变慢或打不开

在“连接”页看它命中了哪条规则。多半是该域名不在国内域名库，被 `final` 送去了代理。把它加进“国内常用域名：直连”组即可。若显示规则集未加载，检查 RuleSet 是否下载成功（首次下载需要代理可用）。

### 某个只连 IP 的国内应用下载失败

确认“中国 IP 库：直连”已启用且排在 `final` 之前；在“连接”页看该 IP 命中的规则。

### 指定服务显示的是入口服务器 IP，不是第二出口

按顺序查三处：

1. 服务端：该域名是否在 `exit2` 规则里，入站 `sniffing` 是否开启；
2. 客户端：该域名是否先被别的组（例如国内域名库）截走。“指定出口”组必须排第一；
3. 应用是否直接连 IP。如果是，需要补 IP 段规则。

### 检测站显示的 IP 和指定服务看到的不一致

检测站域名没放进同一份名单，它走的是普通代理路径。把检测站加入第 06 章的名单（三处同步）。

### DNS 检测显示中国大陆解析器

检查“代理流量 / final”的 DNS 是否只保留国外 DoH，并且“通过代理解析”已开启；检查浏览器是否开了使用国内服务器的“安全 DNS”。

### Windows 关闭 Karing 后上不了网

TUN 或系统代理没有被正确撤销。重新打开 Karing 再正常关闭一次；必要时在“设置 → 网络和 Internet → 代理”里关闭手动代理。名单内网站打不开则是第 07 章 A 层的预期行为。

### WSL 里没有走代理

确认 `.wslconfig` 已生效（`wsl --shutdown` 后重进），Karing 的系统代理已开启；在 WSL 中 `env | grep -i proxy` 应能看到继承的代理变量。

### iPhone 切换 Karing 开/关后，App 卡住不动

已建立的连接不会自动迁移到新路径。从后台完全划掉 App 再打开。

### iPhone 名单内网站全部打不开

中继或第二出口不可用：在服务器上看 `systemctl status app-relay.target`；证书是否过期（`/opt/app-relay/acme/bin/certbot certificates`）；80 端口是否仍然放行以便续期。

### 服务器流量突然暴涨

看 vnStat 的小时统计确认时间段；检查链接是否外泄（必要时更换 UUID）；确认 BT 阻断规则仍在。
