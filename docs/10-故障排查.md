# 10 故障排查

## 定位顺序

从里到外一段一段排除，一次只改一处。先跑一遍健康检查，按它报的根因下手。

```text
① 服务器进程 → ② 服务器端口与防火墙 → ③ 客户端节点参数 → ④ 客户端模式与分流 → ⑤ DNS → ⑥ 二级出口 → ⑦ 防直连
```

| 段 | 检查 |
|---|---|
| ① | `systemctl status xray`；`journalctl -u xray -n 100 --no-pager` |
| ② | `ss -tlnp \| grep 443`；`ufw status`；云防火墙入站规则；海外能通、国内不通则是入口被封 |
| ③ | 链接里的 UUID、`pbk`（公钥）、`sid`、`sni`、端口是否与服务端一致 |
| ④ | 是否为规则模式；Clash Mi“连接”页看命中的规则和出站 |
| ⑤ | `nameserver-policy` 是否覆盖该域名；临时换成全局模式对比 |
| ⑥ | 服务器上直接 `curl --socks5-hostname` 测第二出口 |
| ⑦ | 临时移除策略/描述文件，看问题是否消失 |

## 常见问题

### 完全连不上，Clash Mi 显示超时

先在服务器上看 Xray 是否 `active`、是否监听 443；再确认云防火墙和 `ufw` 都放行了 443。换个网络（手机热点）试一次，区分是服务器问题还是当前网络问题。

### 所有端口都不通，SSH 也连不上

从海外（另一台服务器，或经备用代理）测 443 和 22。海外通、国内不通，就是入口 IP 被整个封锁；海外也不通，是 VPS 宕机，到面板查看或重启。

IP 被封时，先核对是不是重大会议、敏感日期前后。这类时期海外机房 IP 常成片被封，不一定是协议被识别。在面板换 IP，按更换入口 IP 的流程改各处；原 IP 过一两周可能解封，可留作冷备。

### 日志里出现 `REALITY: processed invalid connection` 或握手失败

客户端参数与服务端不匹配：最常见的是把**私钥**当成公钥填进客户端，或 `sid` 不在 `shortIds` 列表中，或 `sni` 不在 `serverNames` 中。也可能是一端开了 `x25519mlkem768`、另一端版本不支持，或误设了过高的 `minClientVer`。

### 升级 Xray 后客户端连不上了

用 `xray-restore` 回到升级前的快照，确认恢复正常；再查新版本的发布说明，看是否有默认值变化。替换二进制前，先用新版本测试现有配置。

### 国内网站变慢或打不开

在“连接”页看它命中了哪条规则。多半是该域名不在国内域名库，被 `MATCH` 送去了代理。把它加进个人补充的直连规则和 `nameserver-policy`。若规则集未加载，检查 `rule-providers` 是否下载成功（首次下载需要代理可用）。

### 某个只连 IP 的国内应用下载失败

确认 `RULE-SET,cn-ip,DIRECT` 排在 `MATCH` 之前；在“连接”页看该 IP 命中的规则。

### 指定服务显示的是入口服务器 IP，不是第二出口

按顺序查三处：

1. 服务端：该域名是否在 `exit2` 规则里，入站 `sniffing` 是否开启；
2. 客户端：该域名是否先被别的规则（例如国内域名库）截走。指定服务的规则必须排在分流规则最前；
3. 应用是否直接连 IP。如果是，需要补 IP 段规则。

### 检测站显示的 IP 和指定服务看到的不一致

检测站域名没放进同一份清单，它走的是普通代理路径。把检测站加进清单，再同步到各处。

### DNS 检测显示中国大陆解析器

检查 `nameserver` 是否只有经代理的国外 DoH（`#PROXY`），`respect-rules` 是否开启；检查浏览器是否开了使用国内服务器的“安全 DNS”。

### Windows 关闭 Clash Mi 后上不了网

TUN 或系统代理没有被正确撤销。重新打开 Clash Mi 再正常关闭一次；必要时在“设置 → 网络和 Internet → 代理”里关闭手动代理。名单内网站打不开是浏览器防直连策略的预期行为。

### WSL 里没有走代理

确认 `.wslconfig` 已生效（`wsl --shutdown` 后重进），且 Clash Mi 的 TUN 已开启。开着 TUN 时，不带代理环境变量的程序会自动由 TUN 接管。如果某个工具要求显式代理，在 WSL 中设置 `HTTP_PROXY` 和 `HTTPS_PROXY` 指向 `http://127.0.0.1:3067`，或开启 Clash Mi 的系统代理让 `autoProxy` 自动继承（可用 `env | grep -i proxy` 确认）。

### iPhone 切换 Clash Mi 开/关后，App 卡住不动

已建立的连接不会自动迁移到新路径。从后台完全划掉 App 再打开。

### iPhone 名单内网站全部打不开

Clash Mi 关闭时打不开是预期行为。Clash Mi 开着也打不开时，按顺序查：

1. 主 Xray 首条规则是否为 `relay-private`，IP 是否为当前入口 IP（换过 IP 后最容易漏）；
2. `systemctl status app-relay.target`，`journalctl -u app-relay-envoy -n 50 --no-pager`。访问日志是 JSON，返回 503 时看 `response_details`、`response_flags` 和 `dns_ms`，区分是域名解析失败还是连不上上游；
3. 证书是否过期：`/opt/app-relay/acme/bin/certbot certificates`；续期时 TCP 80 能否从外网访问；
4. 第二出口是否可用。

### 公网上又能连到 8443

中继的 `xray-egress.json` 恢复了对公网监听的入站（例如从旧备份恢复）。从最新的正式快照恢复它，重启 `app-relay.target`，确认 `ss -ltn` 里没有 8443。

### 服务器流量突然暴涨

看流量统计的小时数据确认时间段和用户；检查配置是否外泄（必要时更换 UUID）；确认 BT 阻断规则仍在。
