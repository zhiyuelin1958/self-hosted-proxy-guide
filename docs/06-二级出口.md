# 06 二级出口（可选）

## 1. 什么时候需要

入口服务器本身就是一个出口。有时你希望某几个服务固定从另一个地区、另一个 IP 出去，例如：

- 某服务在入口服务器所在地区不可用，或对机房 IP 不友好；
- 希望某个账号长期只从一个固定 IP 访问，其他流量没必要绕远路。

做法是**链式代理**：客户端照常连入口服务器，入口服务器按域名判断，把这部分流量再交给第二出口（SOCKS5）。

```text
客户端 ──VLESS+REALITY──► 入口服务器 ──┬── freedom（直接出去）     ► 普通国际流量
                                     └── socks（第二出口）        ► 指定服务
```

客户端不用改节点链接，所有分流决定都在服务端完成，几台设备自动一致。

## 2. 先单独测试第二出口

拿到供应商给的 `<EXIT2_HOST>`、`<EXIT2_PORT>`、`<EXIT2_USER>`、`<EXIT2_PASS>` 后，在入口服务器上测试：

```bash
curl -sS --max-time 10 \
  --socks5-hostname '<EXIT2_USER>:<EXIT2_PASS>@<EXIT2_HOST>:<EXIT2_PORT>' \
  https://www.cloudflare.com/cdn-cgi/trace
```

`ip=` 应为第二出口 IP，`loc=` 为它所在地区。`--socks5-hostname` 表示域名也交给 SOCKS5 一侧解析，入口服务器本地不做 DNS 解析。

> 多数供应商要求把入口服务器 IP 加入白名单，或者只接受账号密码认证，按供应商说明配置。

## 3. 准备“指定服务”域名清单

从 [templates/protected-domains.example.json](../templates/protected-domains.example.json) 开始修改。一个服务往往不止一个域名，清单通常包括：

| 类别 | 说明 | 如何找 |
|---|---|---|
| 主域名 | 服务本身 | 服务官网的地址 |
| 配套域名 | 登录、静态资源、用户上传内容、支付、客服、功能开关/统计 | 浏览器开发者工具 → Network，看页面加载了哪些域名 |
| 服务自己的 IP 段 | 有些客户端直接连 IP | 服务公开的 IP 段说明，或 ASN 查询 |
| 检测站 | 用来验证出口的 IP 查询站 | 见第 08 章，放进同一清单，才能测出“这条路径”的真实出口 |
| STUN/TURN | 实时通信的地址发现 | `stun.l.google.com`、`stun.cloudflare.com` 等 |

**规则用“域名后缀”匹配**：写 `example-service.com` 会同时匹配 `www.example-service.com`、`api.example-service.com`。

同一份清单要用在下面三个地方，三处保持一致：

1. 服务端 Xray 路由（本章）；
2. 客户端“指定出口：优先代理”分流组（第 05 章）；
3. 防直连保护名单（第 07 章）。

## 4. 修改服务端配置

在第 04 章配置的基础上，对照 [server/xray/config.chain.json](../server/xray/config.chain.json)，增加两部分。

**出站**：在 `outbounds` 中加一个 SOCKS5 出站，`tag` 命名为 `exit2`：

```json
{
  "tag": "exit2",
  "protocol": "socks",
  "settings": {
    "servers": [{
      "address": "<EXIT2_HOST>",
      "port": <EXIT2_PORT>,
      "users": [{ "user": "<EXIT2_USER>", "pass": "<EXIT2_PASS>" }]
    }]
  }
}
```

**路由**：在 `routing.rules` 中、`block` 规则之后加三条：

```json
{ "type": "field", "domain": ["domain:example-service.com", "domain:ipinfo.io"], "outboundTag": "exit2" },
{ "type": "field", "ip": ["<服务的 IP 段，CIDR>"], "outboundTag": "exit2" },
{ "type": "field", "network": "udp", "port": "3478,5349,19302-19309", "outboundTag": "exit2" }
```

| 规则 | 作用 |
|---|---|
| `domain:xxx` | 按域名后缀匹配（需要入站开启 `sniffing`，第 04 章已开） |
| `ip` | 兜住直接连 IP、没有域名可嗅探的连接 |
| UDP STUN 端口 | 让 WebRTC 发现的“公网地址”也是第二出口 |

未匹配任何规则的流量走 `outbounds` 中**第一个**出站，所以 `direct`（freedom）必须排在第一位。

`routing.domainStrategy` 设为 `IPIfNonMatch`：先按域名匹配，域名都不中时再解析成 IP 去匹配 IP 规则。

**规则顺序**：`geoip:private` 和 `bittorrent` 的阻断放最前面，保证任何出口都不能被用来访问内网或跑 BT。

完整示例文件中，`"port": 1080` 和 IP 段 `192.0.2.0/24`（RFC 5737 文档网段）都是占位值，换成供应商给的端口和你的服务公开的 IP 段；没有可用的 IP 段就删掉这条规则。

检查并重启：

```bash
sudo xray run -test -config /usr/local/etc/xray/config.json && sudo systemctl restart xray
```

## 5. 端到端验证

客户端保持规则模式，打开：

| 页面 | 期望 |
|---|---|
| `https://<指定服务域名>/cdn-cgi/trace`（若该服务使用 Cloudflare） | `ip=<EXIT2_IP>` |
| <https://ipinfo.io/json>（检测站已放入清单） | 第二出口 IP 与地区 |
| <https://www.cloudflare.com/cdn-cgi/trace> | `ip=<SERVER_IP>`（普通流量仍从入口出去） |

注意：`/cdn-cgi/trace` 只对使用 Cloudflare 的网站有效；不是的话，用清单里的检测站验证。

## 6. 注意事项

- **UDP**：SOCKS5 的 UDP 需要供应商支持（UDP ASSOCIATE）。不支持时 STUN 规则会让相关 UDP 失败，此时宁可失败也不要回退到入口出口。
- **DNS**：Xray 把域名原样交给 SOCKS5，由第二出口解析，因此指定服务的 DNS 解析也发生在第二出口一侧。
- **延迟**：多一跳就多一段延迟，入口和第二出口在地理上越近越好。
- **续费**：第二出口过期后指定服务会直接失败（这正是“不回退”的设计），记得在日历里提醒续费。
