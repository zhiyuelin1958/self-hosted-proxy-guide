# 09 维护、备份与恢复

## 1. 日常查看

| 想知道 | 方法 |
|---|---|
| Xray 是否在运行 | `ssh azureuser@<SERVER_IP> "systemctl is-active xray"` |
| 最近的错误 | `ssh azureuser@<SERVER_IP> "journalctl -u xray -n 50 --no-pager"` |
| 用了多少流量 | 双击 [client/windows/check-traffic.bat](../client/windows/check-traffic.bat)（先改里面的地址） |
| 花了多少钱 | 云平台“成本管理 / 账单”，以此为准 |

## 2. 流量与账单

- `ip -s link` 的计数从开机算起，重启后归零，vnStat 则跨重启累计。两者起点不同，数字对不上是正常的；
- 云厂商通常按**出站**计费，建议设置预算告警（例如达到预期的 50%、80%、100% 各提醒一次）；
- 第二出口单独计费，在日历里记下续费日期；
- 关注免费额度的到期时间（如 Azure 免费账户的 12 个月），到期前决定续用、降配还是迁移。

## 3. 快照与恢复

仓库提供两个脚本，安装到服务器：

```bash
sudo install -m 700 server/scripts/xray-snapshot.py /usr/local/sbin/xray-snapshot
sudo install -m 700 server/scripts/xray-restore.py  /usr/local/sbin/xray-restore
```

| 命令 | 作用 |
|---|---|
| `sudo xray-snapshot known-good` | 打包 Xray 程序、配置、服务单元、规则数据，写入 `/var/backups/xray/<时间>-known-good/`，附 SHA-256 清单 |
| `sudo xray-restore <快照目录> --check` | 校验哈希、解包到临时目录、用快照里的程序测试快照里的配置，**不改动线上文件** |
| `sudo xray-restore <快照目录>` | 先给当前状态再拍一张快照，然后恢复并在 3 秒后重启 Xray |

建议：

- 每次验收通过后拍一张 `known-good`；每次改配置前拍一张 `before-xxx`；
- 把快照下载一份到本地（`scp`）。**快照包含私钥和账号，只能存私密位置**；
- 恢复会中断所有连接，包括你自己正在用的那条；恢复后检查 SSH、`systemctl is-active xray` 和第 08 章的出口。

## 4. 升级策略

Xray 和客户端内核更新很快，偶尔会改变默认行为或握手细节。原则：**先验证，再替换；能回退再动手**。

1. 记录当前可用组合（例：Xray 26.7.28 + Karing 1.2.25 + `minClientVer: 1.8.0`）；
2. `sudo xray-snapshot before-upgrade`；
3. 用新版本程序测试现有配置：下载新版到临时目录，执行 `./xray run -test -config /usr/local/etc/xray/config.json`；
4. 正式升级（`install-release.sh install --version <新版本>`）后，立刻在每种客户端上测握手和出口；
5. 有问题就 `xray-restore` 回到上一张快照。

客户端同理：一台设备先升级、验收，再推广到其他设备。

## 5. 修改保护名单 / 分流规则

名单在三处使用，要一起改：

1. 服务端 Xray 路由（第 06 章）→ 改完 `-test`、重启；
2. 客户端分流组（第 05 章）→ 重新打包导入，或在 Karing 里直接编辑；
3. 防直连（第 07 章）→ Windows 重新执行安装脚本；iPhone 重新发布描述文件并在手机上重装。

## 6. 增加 / 停用用户

- 增加：`xray uuid` 生成新 UUID，`openssl rand -hex 4` 生成 shortId，加入 `clients` 和 `shortIds`，重启，生成新链接；
- 停用：从 `clients` 删除该 UUID（及其 shortId），重启。对方的链接立即失效；
- iPhone 中继的账号在 `/var/lib/app-relay/credentials.json`，改动后重新发布描述文件。

## 7. 服务器迁移

1. 新服务器按第 02～04 章做到 Xray 安装完成；
2. 把旧服务器的 `config.json` 复制过去（UUID、密钥都可沿用），`-test` 后启动；
3. 客户端链接里的 IP 要改成新 IP（重新生成链接或在客户端里编辑地址）；
4. 第二出口如有 IP 白名单，加上新服务器 IP；
5. 第 08 章全套重测，确认后再释放旧服务器。
