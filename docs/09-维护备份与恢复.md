# 09 维护、备份与恢复

## 1. 日常查看

| 想知道 | 方法 |
|---|---|
| Xray 是否在运行 | `ssh root@<SERVER_IP> "systemctl is-active xray"` |
| 最近的错误 | `ssh root@<SERVER_IP> "journalctl -u xray -n 50 --no-pager"` |
| 用了多少流量 | 双击 [client/windows/check-traffic.bat](../client/windows/check-traffic.bat)（先改里面的地址） |
| 计费用量 | VPS 面板，以此为准 |

## 2. 单一来源：入口 IP 和域名清单

入口 IP 和指定服务域名清单会写进很多地方：电脑和手机的 Clash Mi 配置、TUN 排除地址、浏览器策略、服务端 Xray、中继描述文件、健康检查和流量脚本。分头手改迟早会漏。

做法：两样东西各只在一个文件里维护，例如 `entry.json`（入口 IP）和 `protected-domains.json`（域名清单）。再写一个同步脚本：

- 默认只比对：逐处读出当前值，与来源比较，列出差异；
- 加 `--apply` 才改：先备份服务器上要改的文件，Xray 配置改完 `xray run -test` 通过才安装；
- 按结构改 JSON / YAML，不做全文替换；
- 遇到无法自动判断的情况（某处既没有新 IP 也没有旧 IP、规则结构不对）就停下，不做任何改动；
- 浏览器策略、备用客户端这类需要管理员权限或界面操作的地方，只比对，列出手动事项。

## 3. 健康检查

写一个只读的检查脚本，按模块报告，每项给出 PASS / WARN / FAIL：

| 模块 | 检查内容 |
|---|---|
| 1 本机 | 本地端口由哪个进程监听、TUN 网卡、开机自启、各处配置的域名清单是否一致 |
| 2 入口 | 网关、国内 DNS、入口服务器的 ping 和 TCP 22 / 443 握手；8443 应握手失败 |
| 3 服务器 | 服务状态、配置文件权限、时钟差、磁盘、内存、流量估算；经 `exit2` 访问检测站 |
| 4 中继 | Xray 首条规则为 `relay-private` 且 IP 正确、公网无 8443 监听、证书剩余天数；经隧道认证 CONNECT 的出口、无认证返回 407 |
| 5 端到端 | 指定服务经 `3067` 和 TUN 的出口、普通国际出口、国内直连、DNS 解析器、STUN |

要点：

- 只在主客户端独占 `3067`、TUN 正常时才跑端到端模块，避免检测本身产生直连；
- 结论只报一个根因，用退出码区分严重程度，例如 3 = 分流或防泄露失效（立刻停用指定服务）、2 = 阻断故障、1 = 非阻断警告、0 = 全部通过；
- 另设一个参数，在备用线路下经备用代理从海外测入口 443，同时从国内直连测 SSH，用来区分入口被封、Xray 故障和 VPS 宕机；
- 用计划任务每天跑一次快速检查并保存日志，退出码 ≥ 2 时弹窗提醒。日志里的凭据先脱敏再写入。

## 4. 流量与账单

- `ip -s link` 的计数从开机算起，重启后归零；vnStat 跨重启累计。两者起点不同，数字对不上是正常的；
- 按“入站、出站较高值”计费的 VPS，入站和出站都要看；
- 第二出口单独计费，在日历里记下续费日期。

想知道流量花在哪，可以开启 Xray 的统计接口，按用户、入站、出站分别计数：

```json
"stats": {},
"api": {"tag": "api", "listen": "127.0.0.1:10085", "services": ["StatsService"]},
"policy": {
  "levels": {"0": {"statsUserUplink": true, "statsUserDownlink": true}},
  "system": {"statsInboundUplink": true, "statsInboundDownlink": true,
             "statsOutboundUplink": true, "statsOutboundDownlink": true}
}
```

再用 systemd 定时器每小时执行一次 `xray api statsquery --server=127.0.0.1:10085 -reset`，把结果追加到一个 JSON Lines 文件里，按天或小时汇总。`direct` 与 `exit2` 两个出站的读数分别对应普通国际流量和指定服务流量。中继的流量不经过主 Xray，另取它的 veth 网卡计数。统计窗口和计费周期不对齐，计费仍以面板为准。

## 5. 快照与恢复

仓库提供两个脚本，安装到服务器：

```bash
install -m 700 server/scripts/xray-snapshot.py /usr/local/sbin/xray-snapshot
install -m 700 server/scripts/xray-restore.py  /usr/local/sbin/xray-restore
```

| 命令 | 作用 |
|---|---|
| `xray-snapshot known-good` | 打包 Xray 程序、配置、服务单元、规则数据，写入 `/var/backups/xray/<时间>-known-good/`，附 SHA-256 清单 |
| `xray-restore <快照目录> --check` | 校验哈希、解包到临时目录、用快照里的程序测试快照里的配置，**不改动线上文件** |
| `xray-restore <快照目录>` | 先给当前状态再拍一张快照，然后恢复并在 3 秒后重启 Xray |

建议：

- 每次验收通过后拍一张 `known-good`，并注明它对应的状态（域名数、有无中继规则），恢复只用它；每次改配置前拍一张 `before-xxx`；
- 中继的 `xray-egress.json` 也一起备份；
- 把快照下载一份到本地（`scp`）。**快照包含私钥和账号，只能存私密位置**；
- 恢复会中断所有连接，包括你自己正在用的那条；恢复后检查 SSH、`systemctl is-active xray` 和各项出口。

## 6. 升级策略

Xray 和客户端内核更新很快，偶尔会改变默认行为或握手细节。原则：**先验证，再替换；能回退再动手**。

1. 记录当前可用组合（例：Xray 26.7.28 + Clash Mi 1.0.32.1803 / mihomo 1.19.33，REALITY 开启 `x25519mlkem768`）；
2. `xray-snapshot before-upgrade`；
3. 用新版本程序测试现有配置：下载新版到临时目录，执行 `./xray run -test -config /usr/local/etc/xray/config.json`；
4. 正式升级（`install-release.sh install --version <新版本>`）后，立刻在每种客户端上测握手和出口；
5. 有问题就 `xray-restore` 回到上一张快照。

客户端同理：一台设备先升级、验收，再推广到其他设备。

## 7. 修改域名清单

只改清单文件，再运行同步脚本：先比对，确认差异后 `--apply`。脚本列出的手动事项逐条做完：

- Windows 浏览器策略：重新执行安装脚本；
- iPhone、iPad：服务器上重新发布描述文件，在手机上重装；
- 备用客户端：同步拒绝规则。

## 8. 更换入口 IP

入口 IP 被封（所有端口都不通、海外能连上）时，在面板换 IP，然后：

1. 备用客户端里把入口的直连规则改成新 IP；
2. 改入口 IP 来源文件，运行同步脚本 `--apply`。它依次完成：记下旧 IP；登记新 IP 的主机密钥（与旧 IP 的密钥相同才自动登记，不同就停下，先在面板控制台核对指纹）；备份服务器文件；重签中继的 IP 证书；更新中继下载页并重新生成描述文件；更新 Xray 的 `relay-private` 规则；替换本机各文件中的 IP；
3. 重启 Clash Mi，跑一遍深度健康检查；
4. 手机从本地文件重新导入 Clash Mi 配置，再按防直连的验收表复测；
5. 重拍 `known-good` 快照，重新做出口与 IP 质量检测。

## 9. 备用线路

主线路故障时，在电脑上换用备用客户端：

1. 完全退出主客户端，确认 `3067` 无人监听；
2. 启动备用客户端，确认规则模式、TUN 开启、本地端口 `3067`；
3. 备用客户端的全局规则里要有：拒绝全部指定服务域名和 IP 段；入口 IP 直连（有的机场屏蔽目标端口 22，SSH 要直连才能登服务器排查）。这些规则写进客户端的全局覆写，不写进订阅文件，否则订阅自动更新会冲掉；
4. 验证：普通国际出口为备用节点 IP；指定服务经 `3067` 和 TUN 都失败；
5. 切回：退出备用客户端，确认 `3067` 无人监听，启动主客户端，跑健康检查。

备用线路下指定服务不可用，这是设计目标。入口被封时 SSH 也会断，只能在面板换 IP。

## 10. 增加 / 停用用户

- 增加：`xray uuid` 生成新 UUID，`openssl rand -hex 4` 生成 shortId，加入 `clients` 和 `shortIds`，重启，发给对方一份配置；
- 停用：从 `clients` 删除该 UUID（及其 shortId），重启。对方的配置立即失效；
- iPhone 中继的账号在 `/var/lib/app-relay/credentials.json`，改动后重新发布描述文件。

## 11. 服务器迁移

1. 新服务器做到 Xray 安装完成；
2. 把旧服务器的 `config.json` 复制过去（UUID、密钥都可沿用），`-test` 后启动；
3. 按“更换入口 IP”的流程把各处 IP 改成新服务器；
4. 第二出口如有 IP 白名单，加上新服务器 IP；
5. 全套重测，确认后再停用旧服务器。旧服务器可以先关机保留，作冷备。
