# 08 测试与验收

本章是一套可重复的检查。每台设备、每种网络（例如校园网和手机热点）都过一遍，把结果和日期记进自己的测评记录。

下文的 Windows 命令在 PowerShell 中执行。`curl.exe` 是 Windows 自带的 curl。不要写成 `curl`，它在 PowerShell 里是 `Invoke-WebRequest` 的别名。

## 1. 出口检查

Cloudflare 的 trace 接口返回纯文本，其中 `ip=` 是对方看到的你的 IP，`loc=` 是国家代码：

```powershell
# 经规则代理端口（显式代理）
curl.exe -s -x http://127.0.0.1:3067 https://www.cloudflare.com/cdn-cgi/trace
# 不指定代理（走 TUN）
curl.exe -s --noproxy "*" https://www.cloudflare.com/cdn-cgi/trace
```

| 测试 | 期望 |
|---|---|
| 普通国际流量（显式代理 / TUN） | `ip=<SERVER_IP>`，`loc=` 入口所在地 |
| 指定服务、名单内检测站（如 <https://ipinfo.io/json>） | 第二出口 IP 与地区 |
| 国内网站、学校网站 | 能打开、速度正常 |
| 只连 IP 的国内应用（如即时通讯的文件下载） | 正常，命中中国 IP 库直连 |

Clash Mi 的“连接”页能看到每个连接命中的规则和出站。

## 2. HTTP/2 与长连接

规则里拒绝了 UDP 443，浏览器应改用 HTTP/2：

- Chrome 打开开发者工具 → Network，右键表头勾选 Protocol，名单内网站应显示 `h2`；
- 流式输出的网页应用（如在线对话）连续收流一两分钟，不应中断。经第二出口实测 75 秒无断开。

## 3. DNS 检查

| 方法 | 看什么 |
|---|---|
| <https://browserleaks.com/dns> | 列出为你解析的递归 DNS 服务器 |
| <https://ip.net.coffee/> 等站点的 DNS 检测 | 同上，部分会提示“出口国家与 DNS 国家不一致” |

**期望**：走代理的网站，检测到的解析器不出现中国大陆的运营商 DNS。注意：

- 代理流量的 DNS 查询从入口服务器或第二出口一侧发出，所以检测到的 DNS 所在地可能和 HTTP 出口不同，这是正常的；
- 网页检测只覆盖系统 DNS 和浏览器的一种路径。浏览器开了“安全 DNS（DoH）”时会走另一条路径，需要分别测。

## 4. WebRTC 与 STUN

WebRTC 会通过 STUN 服务器询问“我的公网 UDP 地址是什么”，这是泄露本地 IP 最常见的途径。

- 浏览器：打开 <https://browserleaks.com/webrtc>，Public IP 只应有代理出口，没有你本地的公网 IP；
- 命令行（需开 TUN，UDP 不走 HTTP 代理）：

  ```powershell
  python client\tools\stun_check.py
  ```

  显示的映射地址应为你期望的出口（做了二级出口则为第二出口）。

## 5. IPv6

本地网络有公网 IPv6、而代理只处理 IPv4 时，IPv6 流量可能绕过代理。打开 <https://test-ipv6.com/>，看是否检测到你的本地 IPv6。有泄露就在 Clash Mi 中关闭 IPv6，或在系统网卡上禁用 IPv6。

没有公网 IPv6 的网络测不出这个问题，换到有 IPv6 的网络后要补测。

## 6. 故障隔离（最重要的一项）

目的：确认代理坏了时，国内网站照常可用，指定服务直接失败，**不回退直连**。

1. 在服务器上临时停掉 Xray：`systemctl stop xray`；
2. 本机重启 Clash Mi（检验规则缓存能否在代理不可用时加载）；
3. 检查：国内网站和国内 DNS 正常；指定服务解析或连接失败，**不能**显示本地 IP；
4. 恢复：`systemctl start xray`，再次确认出口正常。

## 7. 防直连

| 设备 | 测试 | 期望 |
|---|---|---|
| Windows 浏览器 | 完全退出 Clash Mi 后打开名单内网站 | `ERR_PROXY_CONNECTION_FAILED`；国内网站正常 |
| iPhone、iPad | Clash Mi 开启时访问 `ident.me` | 第二出口 IP |
| iPhone、iPad | 关闭 Clash Mi、改用其他代理、切换 Wi-Fi / 蜂窝 | `ident.me` 和指定服务都失败 |
| iPhone、iPad | 停中继出站后，完全退出并重开 App | 名单内服务不可用；普通网站正常 |
| WSL | 关闭 Clash Mi 后运行受保护命令 | 启动前检查失败，命令不运行 |
| 备用线路 | 切到备用客户端，经 `3067` 和 TUN 访问名单内网站 | 都失败 |

## 8. 速度与稳定性

```powershell
# 5 次新建 HTTPS 请求的总耗时（秒）
1..5 | ForEach-Object { curl.exe -s -o NUL -w "%{time_total}`n" https://www.cloudflare.com/cdn-cgi/trace }
# 小文件下载速度（字节/秒）
curl.exe -s -o NUL -w "%{speed_download}`n" https://speed.cloudflare.com/__down?bytes=10000000
```

新建 HTTPS 的耗时包含本机代理、TLS 握手和服务器响应，和 ping、应用的首包延迟是两回事。小文件下载只是样本，不代表带宽上限。

## 9. 出口 IP 质量：怎么看检测站的结果

常用检测站：[IPInfo](https://ipinfo.io/)、[IP-API](https://ip-api.com/)、[Scamalytics](https://scamalytics.com/)、[Ping0](https://ping0.cc/)、[IPPure](https://ippure.com/)、[Net.Coffee](https://ip.net.coffee/)、[ProxyCheck](https://proxycheck.io/)、[Shodan InternetDB](https://internetdb.shodan.io/)。它们回答的问题不同：

| 类型 | 例子 | 能说明什么 |
|---|---|---|
| 地理位置 / ASN | IPInfo、IP-API、RIPE RDAP | IP 在哪个国家、属于哪个网络运营商、在哪注册 |
| 类型标记 | IP-API 的 `hosting` / `proxy`，各站的“住宅 / 机房” | 该数据库把这个 IP 归为哪类 |
| 风险分 | Scamalytics、IPPure、Ping0、ProxyCheck | 该数据库估计的滥用风险，常按网段或机构推断 |
| 开放端口 | Shodan InternetDB | 扫描到这个 IP 开了哪些端口、被标成什么服务 |

经验：

- 各库经常互相矛盾。同一个 IP，一家标“家庭宽带”，另一家标“机房”，很常见；
- 注册地和广播地可以不同，例如在一个国家注册、经另一个国家的运营商广播；
- 很多评分按网段缓存，查到的未必是你这一个 IP；
- **第三方评分不代表某个具体服务对你的判断**。选出口时先看它能不能稳定使用、IP 是否长期不变，不必追某个分数。

## 10. 验收清单

- [ ] 普通国际、指定服务、国内三类出口均符合预期（每种网络各一次）
- [ ] HTTP/2 生效，长连接不中断
- [ ] DNS 检测无中国大陆解析器出现在代理流量中
- [ ] WebRTC / STUN 无本地公网 IP
- [ ] IPv6 已检查（或注明“当前网络无 IPv6，未测”）
- [ ] 故障隔离：代理不可用时国内正常、指定服务失败不回退
- [ ] 防直连各层按设备验收（如适用）
- [ ] 结果和日期已写入自己的测评记录
