# 08 测试与验收

本章是一套可重复的检查。每台设备、每种网络（例如校园网和手机热点）都过一遍，把结果记进[模板](../templates/计划进度测评模板.md)的“测评”部分。

下文的 Windows 命令在 PowerShell 中执行。`curl.exe` 是 Windows 自带的 curl。不要写成 `curl`，它在 PowerShell 里是 `Invoke-WebRequest` 的别名。

## 1. 出口检查

Cloudflare 的 trace 接口返回纯文本，其中 `ip=` 是对方看到的你的 IP，`loc=` 是国家代码：

```powershell
# 经规则代理端口（显式代理）
curl.exe -s -x http://127.0.0.1:3067 https://www.cloudflare.com/cdn-cgi/trace
# 不指定代理（走 TUN）
curl.exe -s https://www.cloudflare.com/cdn-cgi/trace
```

| 测试 | 期望 |
|---|---|
| 普通国际流量（显式代理 / TUN） | `ip=<SERVER_IP>`，`loc=` 入口所在地 |
| 指定服务（若做了第 06 章） | 第二出口 IP 与地区 |
| 名单内检测站，如 <https://ipinfo.io/json> | 第二出口 |
| 国内网站、学校网站 | 能打开、速度正常 |
| 只连 IP 的国内应用（如即时通讯的文件下载） | 正常，命中“中国 IP 库”直连 |

在 Karing 的“连接”页面可以看到每个连接命中了哪条规则、走了哪个出站，排查分流问题时最直接。

## 2. DNS 检查

| 方法 | 看什么 |
|---|---|
| <https://browserleaks.com/dns> | 列出为你解析的递归 DNS 服务器 |
| <https://ip.net.coffee/> 等站点的 DNS 检测 | 同上，部分会给出“出口国家与 DNS 国家不一致”的提示 |

**期望**：走代理的网站，检测到的解析器不应出现中国大陆的运营商 DNS。注意：

- 代理流量的 DNS 查询从入口服务器或第二出口一侧发出，所以检测到的 DNS 所在地可能和 HTTP 出口不同（例如 DNS 在日本、HTTP 出口在别处）。这是正常的；
- 网页检测只覆盖系统 DNS 和浏览器的一种路径。浏览器开了“安全 DNS（DoH）”时会走另一条路径，需要分别测。

## 3. WebRTC 与 STUN

WebRTC 会通过 STUN 服务器询问“我的公网 UDP 地址是什么”，这是泄露本地 IP 最常见的途径。

- 浏览器：打开 <https://browserleaks.com/webrtc>，看“Public IP”是否只有代理出口，没有你本地的公网 IP；
- 命令行（需开 TUN，UDP 不走 HTTP 代理）：

  ```powershell
  python client\tools\stun_check.py
  ```

  显示的映射地址应为你期望的出口（做了第 06 章则为第二出口）。

## 4. IPv6

如果本地网络有公网 IPv6，而代理只处理 IPv4，IPv6 流量可能绕过代理。检查：

- <https://test-ipv6.com/>：看是否检测到你的本地 IPv6；
- 如果有泄露，在 Karing 中关闭 IPv6 或确认 TUN 同时接管 IPv6，或在系统网卡上禁用 IPv6。

没有公网 IPv6 的网络测不出这个问题，换到有 IPv6 的网络后要补测。

## 5. 故障隔离（最重要的一项）

目的：确认代理坏了时，国内网站照常可用，指定服务直接失败，**不回退直连**。

1. 在服务器上临时停掉 Xray：`sudo systemctl stop xray`；
2. 本机重启 Karing（检验规则缓存能否在代理不可用时加载）；
3. 检查：国内网站和国内 DNS 正常；指定服务解析或连接失败，**不能**显示本地 IP；
4. 恢复：`sudo systemctl start xray`，再次确认出口正常。

## 6. 防直连（第 07 章）

| 设备 | 测试 | 期望 |
|---|---|---|
| Windows 浏览器 | 退出 Karing 后打开名单内网站 | 代理连接错误；普通网站正常 |
| iPhone | Karing 开/关两种状态打开检测页 | 都是第二出口 |
| iPhone | 停中继出站后，完全退出并重开 App | 名单内服务不可用；普通网站正常 |
| WSL | 关闭 Karing 后运行受保护命令 | 启动前检查失败，命令不运行 |

## 7. 速度与稳定性

```powershell
# 5 次新建 HTTPS 请求的总耗时（秒）
1..5 | ForEach-Object { curl.exe -s -o NUL -w "%{time_total}`n" https://www.cloudflare.com/cdn-cgi/trace }
# 小文件下载速度（字节/秒）
curl.exe -s -o NUL -w "%{speed_download}`n" https://speed.cloudflare.com/__down?bytes=10000000
```

解读时注意：

- 新建 HTTPS 的耗时包含本机代理、TLS 握手和服务器响应。它和 ping、应用的首包延迟都是两回事；
- 小文件下载只是样本，不代表带宽上限；
- 长连接（如流式输出的网页应用）可以打开一个持续输出的页面观察一两分钟，看是否中断。

参考样例（2026-11，日本入口 + 新加坡第二出口，校园网）：

| 项目 | 结果 |
|---|---|
| 普通国际 trace，5 次新建 HTTPS | 5/5 成功，0.51 s～0.67 s，中位数 0.58 s |
| 经第二出口的 trace | 约 1.0 s～1.3 s |
| 下载（本机经入口 / 入口经第二出口） | 约 15 Mbps / 20 Mbps |
| 流式长连接（两段分别测） | 均持续 75 s 无中断 |

## 8. 出口 IP 质量：怎么看检测站的结果

常用检测站：[IPInfo](https://ipinfo.io/)、[IP-API](https://ip-api.com/)、[Scamalytics](https://scamalytics.com/)、[Ping0](https://ping0.cc/)、[IPPure](https://ippure.com/)、[Net.Coffee](https://ip.net.coffee/)。它们回答的问题不同：

| 类型 | 例子 | 能说明什么 |
|---|---|---|
| 地理位置 / ASN | IPInfo、IP-API | IP 在哪个国家、属于哪个网络运营商 |
| 类型标记 | IP-API 的 `hosting`/`proxy`，各站的“住宅/机房” | 该数据库把这个 IP 归为哪类 |
| 风险分 | Scamalytics、IPPure、Ping0 | 该数据库估计的滥用风险，常按网段或机构推断 |

经验：

- 各库经常互相矛盾。同一个 IP，一家标“家庭宽带”，另一家标“机房”，很常见；
- 很多评分按网段缓存，查到的未必是你这一个 IP；
- “共享人数”“是否独享”之类是网站估计，不能证明供应商的承诺；
- **第三方评分不代表某个具体服务对你的判断**。选出口时先看它能不能稳定使用、IP 是否长期不变，不必追某个分数。

## 9. 验收清单

- [ ] 普通国际、指定服务、国内三类出口均符合预期（每种网络各一次）
- [ ] DNS 检测无中国大陆解析器出现在代理流量中
- [ ] WebRTC / STUN 无本地公网 IP
- [ ] IPv6 已检查（或注明“当前网络无 IPv6，未测”）
- [ ] 故障隔离：代理不可用时国内正常、指定服务失败不回退
- [ ] 防直连各层按设备验收（如适用）
- [ ] 结果和日期已写入自己的测评记录
